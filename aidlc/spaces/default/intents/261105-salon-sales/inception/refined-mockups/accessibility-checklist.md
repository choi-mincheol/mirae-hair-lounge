# 접근성 점검표: 미용 제품 판매 관리

> 근거: Q3 답 "B. 기본만"(입력 칸 라벨, 글자 오류 안내, 색만으로 상태를 표시하지 않기. 키보드·대비 기준은 따로 맞추지 않음). 요구사항 `inception/requirements-analysis/requirements.md`의 FR3.5·FR7.6(재고 부족·연체를 글자로도 표시), FR10.3(오류 안내), NFR12(최신 Chrome·Edge). 화면은 `mockups.md`, 컴포넌트는 `interaction-spec.md`, 스타일은 `design-system-mapping.md`.

이 앱은 WCAG 2.1 AA 인증을 목표로 하지 않습니다(Q3). 아래 "맞추는 것"은 모든 화면에서 지키고, "맞추지 않는 것"은 따로 검사하지 않습니다.

## 1. 맞추는 것 (모든 화면)

| 번호 | 항목 | 어떻게 | 어디서 확인 | 근거 |
|---|---|---|---|---|
| A1 | 모든 입력 칸에 보이는 라벨 | `<label for>`로 연결. 자리 표시 글자(placeholder)만으로 라벨을 대신하지 않는다 | S01, S04, S06, S09, S12, S14, S18, S19 | Q3 |
| A2 | 필수 칸 표시 | 라벨 뒤 `*` + `required` 속성 | 같은 화면 | Q3 |
| A3 | 오류는 글자로 | 칸 아래 오류 문구 + 칸과 `aria-describedby` 연결. 빨간 테두리만으로 알리지 않는다 | 모든 폼 | FR10.3, Q3 |
| A4 | 화면 위 오류 요약 | "입력값을 확인해 주세요. 오류 n건" (`role="alert"`) | 모든 폼 | FR10.3 |
| A5 | 색만으로 상태를 알리지 않기 | 재고 부족, 연체, 완납, 승인 대기, 취소, 중지, 입금 완료는 늘 글자 배지 | S02, S03, S08, S10, S11, S13 | FR3.5, FR7.6, Q3 |
| A6 | 바뀐 항목 표시 | 비교 화면의 바뀐 줄은 배경색 + 굵은 글씨 + "(바뀜)" 글자 | S14 확인창, S15 | Q3, Q6 |
| A7 | 페이지 언어 | `<html lang="ko">` | `layout/app.html` | FR10.1 |
| A8 | 화면마다 제목 하나 | 화면 제목은 `<h1>`, 영역 제목은 `<h2>` 순서. `<title>`은 "화면 제목 - Mirae 판매 관리" | 모든 화면 | [assumption] |
| A9 | 표는 표로 | `<table>`, `<th scope="col">`, 휴대폰 카드 모양도 같은 표 구조(`.table-stack`) | 목록 화면 | [assumption] |
| A10 | 버튼과 링크 구분 | 화면 이동은 링크(`<a>`), 동작은 버튼(`<button>`). `<div>`에 클릭을 달지 않는다 | 모든 화면 | [assumption] |
| A11 | 같은 이름 버튼 구분 | 표의 줄마다 있는 버튼에 대상 이름을 넣는다(예: `aria-label="2회차 입금 처리"`, "OO 염색약 - 7N 빼기") | S03, S06, S12, S13 | [assumption] |
| A12 | 알림을 읽어 주기 | 오류 알림 `role="alert"`, 성공·안내 `role="status"` | FlashAlert | [assumption] |
| A13 | 포커스 표시를 지우지 않기 | `outline: none` 금지, Bootstrap 기본 포커스 표시 유지 | `app.css` | [assumption] |
| A14 | 화면 확대 | 브라우저 200% 확대에서 내용이 잘리지 않음(반응형 배치로 자연스럽게 확보) | 모든 화면 | Q2 |
| A15 | 자동으로 사라지는 알림 없음 | 알림은 닫기 버튼으로 닫는다 | FlashAlert | [assumption] |

## 2. 맞추지 않는 것 (Q3)

| 항목 | 지금 상태 |
|---|---|
| 키보드만으로 모든 기능 사용 검사 | 따로 검사하지 않는다. 기본 HTML 요소와 Bootstrap 창·메뉴의 키보드 동작(Tab, Enter, Esc)은 그대로 남는다 |
| 글자 대비 4.5:1 측정 | 따로 측정하지 않는다. Bootstrap 기본 색을 그대로 쓴다 |
| 화면 읽기 프로그램 검사 | 따로 검사하지 않는다 |
| 터치 대상 44px 이상 | 따로 맞추지 않는다. 휴대폰에서 주요 버튼은 폭 전체를 써서 누르기 쉽게 한다 |

## 3. 확인 방법

- Code Generation에서 컨트롤러 테스트(MockMvc)로 확인할 수 있는 항목: 오류 응답 화면에 해당 칸의 오류 문구가 있는지(A3), 상태 배지 글자가 있는지(A5). [team-practices] [assumption]
- 나머지는 화면을 만든 뒤 Chrome에서 직접 열어 보고 이 표에 체크한다(PC 폭과 휴대폰 폭 각각).
