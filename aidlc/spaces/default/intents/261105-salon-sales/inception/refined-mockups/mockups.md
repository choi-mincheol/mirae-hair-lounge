# 화면 설계: 미용 제품 판매 관리 (mirae-hair-lounge)

## 근거

- 요구사항: `inception/requirements-analysis/requirements.md` (FR1~FR10, NFR1~NFR12)
- 작업 방식: `inception/practices-discovery/team-practices.md` (Thymeleaf 서버 렌더링, 화면별 JavaScript는 정적 파일로 분리, npm 같은 프런트엔드 빌드 도구 없음, `127.0.0.1` 전용)
- 이 단계의 질문과 답: `inception/refined-mockups/refined-mockups-questions.md` (Q1~Q10)
- 이 계획에는 Rough Mockups(와이어프레임, 사용자 흐름)와 User Stories 단계가 없습니다. 그래서 화면은 요구사항에서 바로 설계했고, 없는 문서의 내용을 지어내지 않았습니다.
- 태그: `[FRn]`은 요구사항, `[Qn]`은 이 단계의 답, `[assumption]`은 이 문서가 세운 가정(7절에 모음)입니다.
- 함께 보는 문서: 컴포넌트와 동작은 `interaction-spec.md`, 스타일 도구와 색·간격은 `design-system-mapping.md`, 접근성 점검표는 `accessibility-checklist.md`.

## 1. 요구사항과 달라진 점 (할부와 입금)

Q9, Q10 답으로 할부와 입금 처리가 승인된 요구사항보다 단순해졌습니다. `requirements.md`는 승인된 그대로 두고, 차이는 여기에 적습니다. 다음 단계(Domain Design)는 이 절을 따릅니다.

| 요구사항 | 승인된 내용 | 바뀐 내용 | 근거 |
|---|---|---|---|
| FR7.1 | 회차 수와 첫 예정일로 자동으로 채운 뒤, 사용자가 각 회차를 고칠 수 있다 | 개월 수로 자동 균등 분배만 한다. 회차 금액과 예정일은 고칠 수 없다. 회차 합계는 늘 판매 금액과 같으므로 "할부 합계가 판매 금액과 다릅니다" 오류는 생기지 않는다 | Q9, Q10 |
| FR7.2 | 입금일, 금액, 입금 수단, 메모를 넣고 여러 번 나눠 입금한다 | 회차 줄의 "입금" 버튼을 누르면 그 회차 금액 전체가 오늘 날짜로 입금 처리된다. 금액·수단·메모 입력과 나눠 입금은 없다 | Q9, Q10 |
| FR7.3 | 잘못 등록한 입금을 취소하고 이력을 남긴다 | 유지. 회차 줄의 "입금 취소" 버튼(관리자)으로 한다 | Q10 |
| FR7.7 | 회차의 예정일과 금액을 바꿀 수 있다 | 없앤다 | Q10 |
| 남은 질문(요구사항 8절) | 할부 판매의 금액을 고칠 때 회차 처리 미정 | 아직 입금되지 않은 회차들에 (새 판매 금액 − 입금 합계)를 다시 똑같이 나눈다. 끝전은 마지막 회차에 더한다 | Q10 |

그대로 유지되는 것: 판매별·거래처별 미수금 표시(FR7.4), 연체 판단(FR7.5, 입금은 앞 회차부터 채움, 예정일 당일은 연체 아님), 연체 강조(FR7.6), 입금이 있는 판매는 입금을 먼저 취소해야 판매를 취소할 수 있음(FR6.5).

세부 규칙:

- 개월 수는 1~36 사이 정수다. [assumption]
- 첫 예정일 기본값은 판매일의 다음 달 같은 날이고, 바꿀 수 있다. 다음 회차는 매달 같은 날이며, 그 날짜가 없는 달(예: 31일)은 그 달 마지막 날이다. [assumption]
- 예: 판매 금액 100,000원, 3개월이면 33,333원, 33,333원, 33,334원. [FR7.1]
- "입금" 버튼은 가장 앞의 미입금 회차에만 켜진다. 입금이 앞 회차부터 채워진다는 연체 규칙(FR7.5)과 화면이 어긋나지 않게 하기 위해서다. [assumption]
- "입금 취소" 버튼은 가장 뒤의 입금된 회차에만 켜진다. 같은 이유다. [assumption]
- 입금과 입금 취소는 관리자만 한다. 직원에게는 버튼이 보이지 않는다. [FR7.2] [assumption]
- 판매 금액이 바뀌어 새 판매 금액이 입금 합계보다 작아지면 저장을 거부하고 "입금된 금액보다 작게 바꿀 수 없습니다. 입금을 먼저 취소하세요."를 보여준다. [assumption]
- 모든 회차가 입금된 판매의 금액을 바꾸려 하면 저장을 거부하고 "입금되지 않은 회차가 없어 금액을 바꿀 수 없습니다."를 보여준다. [assumption]
- 입금 기록이 하나라도 있으면 개월 수와 결제 수단(외상·할부에서 다른 수단으로)을 바꿀 수 없다. 입금이 없을 때 개월 수를 바꾸면 회차 전체를 다시 나눈다. [assumption]

## 2. 공통 화면 틀 [Q1] [Q2]

모든 화면은 왼쪽 세로 메뉴와 오른쪽 본문으로 된 같은 틀을 씁니다. (아래 그림의 한글은 글자 폭이 달라 칸이 조금 어긋나 보일 수 있습니다.)

```
+-----------------+------------------------------------------------+
| 대시보드        | 화면 제목 (h1)                                  |
| 판매            | [알림: 저장했습니다 / 오류 안내]                 |
|   판매 목록     |                                                |
|   판매 등록     | 본문                                            |

+-----------------+------------------------------------------------+
```

- 지금 보고 있는 메뉴는 굵은 글씨와 왼쪽 막대로 표시하고, 화면 읽기 프로그램용으로 "현재 화면"을 알린다.
- "승인 요청" 옆 숫자는 대기 중인 요청 수다. 0이면 숫자를 숨긴다. [FR9.1]
- 알림 영역은 화면 제목 바로 아래에 있다. 저장·취소 같은 동작의 결과와 서버 오류를 글자로 보여준다.

## 4. 화면별 설계

### S01 로그인 [FR1.1] [FR1.5]

```
+----------------------------------+
|        Mirae 판매 관리            |
|                                  |
|  아이디     [                  ] |
|  비밀번호   [                  ] |
|                                  |
|  [          로그인            ]  |
|                                  |
|  (오류) 아이디 또는 비밀번호가    |
|         올바르지 않습니다         |
+----------------------------------+
```

- 화면 가운데 카드 하나. 메뉴 틀은 없다.
- 틀린 비밀번호, 사용 중지 계정 모두 같은 문구 "아이디 또는 비밀번호가 올바르지 않습니다"를 보여준다(어느 쪽인지 알려주지 않음). 아이디 칸 값은 남기고 비밀번호 칸은 비운다. [FR1.1] [FR1.3] [assumption]
- 로그인이 만료되어 넘어온 경우 "로그인 시간이 지나 다시 로그인해 주세요."를 보여주고, 로그인 후 원래 보던 화면으로 돌아간다. [FR1.5] [assumption]
- 로그아웃 후에는 "로그아웃했습니다."를 보여준다.

### S02 대시보드 [FR9]

관리자:

```
+----------------+----------------+----------------+
| 오늘 판매      | 이번 달 판매    | 승인 대기       |
| 1,250,000원    | 18,400,000원   | 3건            |
+----------------+----------------+----------------+
| 연체 판매 (2)                       [전체 보기]  |
|  OO헤어 | 연체 120,000원 | 가장 오래된 예정일 10/05 |
+-------------------------------------------------+
| 재고 부족 (4)                       [전체 보기]  |
|  OO 염색약 - 7N | 현재 2 / 최소 5 | 재고 부족     |
+-------------------------------------------------+
| 최근 판매 10건                      [전체 보기]  |
|  11/05 14:20 | OO헤어 | 외상·할부 | 330,000원     |
+-------------------------------------------------+
```

- 위쪽 숫자 카드 3개, 아래로 연체 판매, 재고 부족, 최근 판매 목록. 휴대폰에서는 모두 한 줄씩 쌓인다.
- 각 카드와 목록 줄은 해당 목록 화면으로 가는 링크다. "오늘 판매"는 오늘로 거른 판매 목록(S11), "승인 대기"는 S15, 연체 줄은 판매 상세(S13), 재고 부족 줄은 "재고 부족만" 거른 상품 목록(S03)으로 간다. [FR9.3]
- 목록에 데이터가 없으면 그 칸 안에 "없음"을 보여준다(예: "연체 판매 없음"). [FR9.3]
- 연체와 재고 부족은 빨간·주황 배지와 함께 "연체", "재고 부족" 글자를 쓴다. [FR3.5] [FR7.6]

직원: 숫자 카드 대신 "내 요청" 카드(대기 n건, 최근 처리 결과 3건)를 두고, 재고 부족과 최근 판매 10건을 보여준다. 매출 금액 합계와 연체 판매는 보여주지 않는다. 최근 판매 목록의 판매 금액은 보인다(판매 조회 권한). [FR9.2] [assumption]

### S03 상품 목록 [FR2.4] [FR3.5]

```
[상품명·브랜드·바코드 검색      ] [분류: 전체 v] [판매 여부: 판매 중 v] [ ] 재고 부족만 [검색]
                                                                  [+ 상품 등록]
+-------------+------+------+--------+--------+------+-----------+------+
| 상품명       | 분류  | 브랜드 | 옵션    | 판매가   | 재고  | 상태       |      |
+-------------+------+------+--------+--------+------+-----------+------+
| OO 염색약    | 염색약 | OO   | 7N     | 9,000원 | 2    | 재고 부족   | 내역  |
|             |      |      | 8N     | 9,000원 | 15   |            | 내역  |
| OO 샴푸     | 샴푸  | OO   | 기본    | 15,000원| 30   |            | 내역  |
+-------------+------+------+--------+--------+------+-----------+------+
전체 47건 중 1-20       [< 이전] 1 2 3 [다음 >]
```

- 상품 한 개가 옵션 수만큼 줄을 차지하고, 상품명·분류·브랜드 칸은 첫 줄에만 쓴다. 상품명은 상품 수정(S04)으로 가는 링크(관리자), "내역"은 재고 변동 내역(S07)으로 간다.
- "판매 여부" 기본값은 "판매 중"이고 "판매 중지", "전체"로 바꿀 수 있다. 판매 중지된 상품·옵션 줄은 회색 글씨에 "판매 중지" 배지. [FR2.5]
- "재고 부족만"은 FR3.5 조건(현재 재고 ≤ 최소 재고)의 옵션이 있는 상품만 보여준다. [assumption]
- 결과가 없으면 표 대신 "조건에 맞는 상품이 없습니다"와 [조건 초기화] 버튼. 상품이 하나도 없으면 관리자에게 "등록된 상품이 없습니다. 첫 상품을 등록해 주세요."와 [+ 상품 등록]을 보여준다. [FR2.4]
- 한 페이지는 20건이며, 페이지를 넘겨도 검색 조건을 유지한다(조건은 주소의 검색 값으로 남음). [FR10.4]
- 직원에게는 [+ 상품 등록] 버튼이 없고 상품명은 링크가 아니다.
- 휴대폰: 상품 하나가 카드 한 장이고, 카드 안에 옵션별로 "7N · 9,000원 · 재고 2 · 재고 부족" 줄이 들어간다.

```
  판매 여부     (o) 판매 중  ( ) 판매 중지

+-----------+------------+---------+---------+--------+---------+------+
```

- `*`는 필수 칸이며 라벨에 "(필수)"를 함께 읽히게 한다. 금액은 0 이상의 원 단위 정수만 받는다. [FR2.6]

- 판매 중 → 판매 중지로 바꿔 저장하면 확인창 "이 상품은 판매 등록에서 고를 수 없게 됩니다. 지난 판매와 실적에는 그대로 나옵니다."를 거친다. [FR10.2]
- 휴대폰: 옵션 표는 옵션마다 카드 한 장(칸이 위아래로 쌓임)으로 바뀐다.

### S10 거래처 상세 [FR4.3]

- 위쪽: 상호, 담당자, 연락처, 주소, 메모, 상태. 관리자에게 [수정] 버튼.
- 요약 카드: 기간 구매 합계, 미수금 합계, 연체 금액(있을 때 "연체" 배지와 가장 오래된 연체 예정일).
- 판매 내역 표: 기간 선택(기본 이번 달), 판매 일시, 판매 번호, 결제 수단, 판매 금액, 미수금, 상태. 판매 번호를 누르면 S13.
- 할부 일정 표: 이 거래처의 미입금 회차를 예정일순으로(판매 번호, 회차, 예정일, 금액, 상태). 연체 회차는 "연체" 배지.
- 판매가 없으면 "이 기간 판매가 없습니다", 할부가 없으면 "남은 할부가 없습니다".

```
|  결제 수단   외상·할부 (3개월)                  |
|  품목        OO 염색약 - 7N x 3   27,000원     |
|              OO 샴푸 - 기본 x 10 150,000원     |
|  할인        10% (-17,700원)                   |
|  판매 금액   159,300원                         |
|  할부        12/05 53,100원 · 01/05 53,100원 · |
|              02/05 53,100원                    |
|                         [돌아가서 고치기] [저장] |
+---------------------------------------------+
```

- [저장]을 누르면 버튼이 꺼지고 "저장 중..."으로 바뀌어 두 번 누를 수 없다. 서버도 같은 요청을 한 건으로만 처리한다. [FR5.6]
- 저장되면 판매 상세(S13)로 가고 알림 "판매 S-0123을 저장했습니다."를 보여준다.
- 서버가 거부하면(재고 부족 등) 확인창을 닫고 판매 등록 화면 위 알림에 이유를 보여주며, 입력한 값은 그대로 둔다. [FR3.3] [FR10.3]

### S13 판매 상세 [FR5.7] [FR6.2] [FR6.5] [FR7.2~FR7.6] [Q9] [Q10]

```
판매 S-0123                         [정상] [연체]
  판매 일시 2026-11-05 14:20 · 거래처 OO헤어 강남점 · 외상·할부 · 등록 홍길동(11/05 14:21)
  메모 -
                               관리자: [수정] [판매 취소]
                               직원:   [수정 요청] [취소 요청]

품목
| 상품 - 옵션      | 수량 | 단가     | 금액      |
| OO 염색약 - 7N   | 3   | 9,000원  | 27,000원  |
| OO 샴푸 - 기본   | 10  | 15,000원 | 150,000원 |
                 품목 합계 177,000원 · 할인 10% -17,700원 · 판매 금액 159,300원

할부와 입금
  판매 금액 159,300원   입금 합계 53,100원   남은 금액 106,200원   연체 53,100원 (예정일 2026-12-05부터)
+------+------------+-----------+---------------------+---------------+
| 회차  | 예정일       | 금액       | 상태                  |               |
| 1    | 2026-12-05 | 53,100원   | 입금 완료 (12/04)      | [입금 취소]     |
| 2    | 2027-01-05 | 53,100원   | 연체                  | [입금]         |
| 3    | 2027-02-05 | 53,100원   | 미입금                 |               |
+------+------------+-----------+---------------------+---------------+

변경 이력
| 일시              | 처리자            | 내용                                   |
| 2026-12-04 10:12 | 홍길동             | 1회차 입금 53,100원                      |
| 2026-11-05 14:21 | 홍길동             | 판매 등록                                |
```

- 위 그림은 오늘이 2027-01-06인 경우다. 상태 배지: "정상" 또는 "취소", 그리고 해당할 때 "승인 대기", "연체", "완납".
- 할부와 입금 영역은 결제 수단이 외상·할부일 때만 있다. 위쪽 줄에 판매 금액, 입금 합계, 남은 금액을 보여주고, 연체가 있으면 연체 금액과 가장 오래된 연체 예정일을 붉은 글씨와 "연체" 글자로 보여준다. [FR7.4] [FR7.6] [Q7]
- 회차 상태는 "입금 완료 (입금일)", "미입금", "연체"(예정일이 오늘보다 앞이고 미입금, FR7.5) 세 가지다. [FR7.5] [Q9]
- [입금](관리자, 가장 앞의 미입금 회차에만): 확인창 "2회차 53,100원을 오늘(2027-01-06) 입금으로 처리할까요?" → 처리하면 상태가 "입금 완료 (01/06)"로 바뀌고 남은 금액과 연체 표시가 다시 계산되며, 변경 이력에 한 줄이 남는다. [Q9] [Q10]
- [입금 취소](관리자, 가장 뒤의 입금된 회차에만): 확인창 "1회차 입금(53,100원, 12/04)을 취소할까요? 남은 금액이 53,100원 늘어납니다." → 취소하면 "미입금" 또는 "연체"로 돌아가고 이력에 남는다. [FR7.3] [Q10]
- 모든 회차가 입금되면 위쪽 줄에 "완납" 배지가 붙고 [입금] 버튼은 없어진다. [FR7.4]
- [판매 취소](관리자): 입금된 회차가 있으면 버튼을 누를 때 "입금 기록이 있어 판매를 취소할 수 없습니다. 입금을 먼저 취소하세요."를 보여준다. 없으면 확인창 "판매 S-0123을 취소할까요? 재고가 돌아오고(7N +3, 기본 +10) 실적과 미수금에서 빠집니다." → 취소 후 상태 "취소", 버튼은 모두 사라진다. [FR3.4] [FR6.5] [FR10.2]
- 승인 대기 요청이 있으면 위쪽에 안내 줄 "직원 김OO의 수정 요청이 승인을 기다리고 있습니다. [요청 보기]"를 보여주고, 직원의 [수정 요청] [취소 요청] 버튼은 꺼진다(한 판매에 대기 요청은 하나). 관리자의 [요청 보기]는 S15 비교 화면으로 간다. [FR6.3]
- 직원이 보는 화면에는 처리된 자기 요청의 결과 줄("수정 요청이 거절되었습니다: 사유 …")이 있다. [FR6.4]
- 변경 이력은 최신순이며, 수정 기록은 [자세히]를 누르면 바꾸기 전 값과 바꾼 뒤 값을 항목별로 펼쳐 보여준다. 요청으로 반영된 변경은 "요청 김OO · 승인 홍길동"으로 적는다. 이력에는 지우기 버튼이 없다. [FR6.2] [FR6.4]
- 휴대폰: 품목, 회차, 이력 표는 줄마다 카드가 되고, 회차 카드 오른쪽 아래에 [입금] 버튼이 있다.

### S14 판매 수정 (관리자) / 수정 요청 (직원) [FR6.1] [FR6.3] [Q6]

- 화면 모양은 판매 등록(S12)과 같고, 현재 값이 채워져 있다. 위쪽 제목만 다르다: 관리자 "판매 S-0123 수정", 직원 "판매 S-0123 수정 요청".
- 직원 화면에는 맨 아래에 "요청 사유 *" 칸이 있고, 버튼이 [요청 보내기]다. 요청을 보내면 판매는 바뀌지 않고 판매 상세로 돌아가 알림 "수정 요청을 보냈습니다. 관리자가 승인하면 반영됩니다."를 보여준다. [FR6.3]
- 저장(또는 요청 보내기) 전에 확인창으로 바뀌는 항목만 "바꾸기 전 → 바꾼 뒤"로 보여준다(예: "OO 염색약 - 7N 수량 3 → 5", "판매 금액 159,300원 → 175,500원"). [Q5] [assumption]
- 외상·할부 판매: 판매 금액이 바뀌면 할부 표가 1절 규칙대로 미입금 회차를 다시 나눈 모습으로 바로 바뀐다. 입금된 회차는 회색으로 고정되어 표시된다. 입금이 있으면 개월 수와 결제 수단 칸은 꺼져 있고 옆에 "입금 기록이 있어 바꿀 수 없습니다"를 쓴다. [Q10]
- 판매 일시, 거래처, 메모, 품목, 수량, 할인, 결제 수단을 바꿀 수 있다. 재고 조정 규칙은 FR3.4를 따르고, 재고가 모자라면 저장을 거부하고 이유를 보여준다. [FR3.4] [FR6.1]
- 직원의 "취소 요청"은 화면 이동 없이 판매 상세에서 창으로 연다: "판매 S-0123 취소를 요청합니다. 사유 * [      ] [요청 보내기]". [FR6.3] [Q6]

### S15 승인 요청 목록·비교 (관리자) [FR6.4] [Q6]

목록:

```
[상태: 대기 v] [기간 ~ ]                                      
+-----------------+--------+------+--------+---------------------------+
| 요청 일시          | 판매    | 종류  | 요청자  | 사유                        |
| 2026-11-05 15:02 | S-0123 | 수정  | 김OO   | 수량을 잘못 입력했습니다          |
| 2026-11-05 11:30 | S-0122 | 취소  | 김OO   | 손님이 구매를 취소했습니다         |
+-----------------+--------+------+--------+---------------------------+
```

- 상태 기본값은 "대기"이고 "승인", "거절", "전체"로 바꿀 수 있다. 줄을 누르면 비교 화면으로 간다. 대기가 없으면 "승인을 기다리는 요청이 없습니다".

비교 화면:

```
수정 요청 · 판매 S-0123 · 요청 김OO (2026-11-05 15:02)
사유: 수량을 잘못 입력했습니다

+--------------------+--------------------+--------------------+
| 항목                | 지금                | 요청한 내용           |
| OO 염색약 - 7N 수량  | 3                  | 5  (바뀜)           |
| 판매 금액            | 159,300원          | 175,500원  (바뀜)   |
| 할부 2회차           | 53,100원           | 61,200원  (바뀜)    |
| 할부 3회차           | 53,100원           | 61,200원  (바뀜)    |
| 거래처              | OO헤어 강남점        | OO헤어 강남점         |
+--------------------+--------------------+--------------------+
                               [거절]   [승인]
```

- 바뀌는 칸은 굵은 글씨, 연한 노란 배경, "(바뀜)" 글자로 표시한다. 바뀌지 않는 항목은 기본으로 접혀 있고 [모든 항목 보기]로 펼친다. [Q6] [assumption]
- 취소 요청은 "판매 취소"와 재고가 돌아오는 내용(예: "7N +3, 기본 +10")을 보여준다.
- [승인]: 확인창 "이 요청을 승인하면 판매 S-0123이 바뀌고 재고가 조정됩니다." → 승인 시점 재고로 다시 검사해, 반영할 수 없으면(재고 부족, 입금된 금액보다 작아짐 등) 승인하지 않고 이유를 보여준다. [FR6.4] [Q10]
- [거절]: 창에서 "거절 사유 *"를 받는다. 비어 있으면 "거절 사유를 입력하세요". [FR6.4]
- 처리한 요청 화면은 결과(승인/거절, 처리자, 일시, 거절 사유)를 보여주고 버튼은 없다.

### S16 내 요청 (직원) [FR6.4]

- 표: 요청 일시, 판매 번호(링크), 종류(수정/취소), 상태(대기/승인/거절), 처리 일시, 거절 사유. 최신순.
- 요청이 없으면 "보낸 요청이 없습니다".

### S17 판매 실적 (관리자) [FR8]

```
[기간 2026-11-01 ~ 2026-11-30] [단위: (o) 일별 ( ) 월별] [조회]
탭: [기간별] [상품·옵션별] [분류별] [결제 수단별]

요약: 판매 34건 · 품목 금액 5,300,000원 · 할인 -120,000원 · 판매 금액 5,180,000원 · 이익 1,640,000원

기간별 (일별)
| 날짜        | 판매 건수 | 품목 금액     | 할인        | 판매 금액     | 이익        |
| 2026-11-05 | 6       | 1,300,000원 | -50,000원  | 1,250,000원 | 410,000원  |
| 합계        | 34      | 5,300,000원 | -120,000원 | 5,180,000원 | 1,640,000원 |
```

- 위쪽 요약 줄은 탭과 관계없이 늘 보인다. 이익은 FR8.4 계산(판매 금액 − 판매 당시 매입가 × 수량 합계)이다. [FR8.1] [FR8.4]
- 상품·옵션별 탭: 순위, 상품 - 옵션, 판매 수량, 품목 금액. 금액, 수량, 상품명 순 정렬. [FR8.2]
- 분류별 탭: 분류, 품목 금액, 비율(%). [FR8.3]
- 결제 수단별 탭: 결제 수단, 판매 건수, 판매 금액. [FR8.5]
- 상품·옵션별과 분류별 표 아래에는 "품목 금액 합계 5,300,000원 − 할인 120,000원 = 판매 금액 5,180,000원" 줄을 둔다. [FR8.6]
- 취소된 판매는 빠지며 표 위에 "취소된 판매는 포함하지 않습니다"를 작게 쓴다. 판매가 없으면 표 대신 "해당 기간 판매가 없습니다". [FR8.6]
- 시작일이 종료일보다 늦으면 "시작일은 종료일보다 늦을 수 없습니다". [assumption]
- 탭과 기간은 주소의 검색 값으로 남아, 새로고침해도 같은 화면이 나온다. [assumption]

### S18 직원 계정 관리 (관리자) [FR1.3]

- 표: 아이디, 이름, 역할(관리자/직원), 상태(사용 중/사용 중지), 만든 날, [사용 중지] 또는 [다시 사용].
- 위쪽 [+ 직원 계정 만들기]는 창으로 연다: 아이디(필수, 중복 불가), 이름(필수), 초기 비밀번호(필수, 8자 이상). 만들면 알림 "직원 계정 kim을 만들었습니다. 초기 비밀번호를 직원에게 전해 주세요." [FR1.3] [FR1.6]
- [사용 중지]: 확인창 "kim 계정은 더 이상 로그인할 수 없습니다." 자기 자신의 관리자 계정에는 버튼이 없다. [FR10.2] [assumption]

### S19 비밀번호 변경 [FR1.6]

- 칸: 현재 비밀번호, 새 비밀번호(8자 이상), 새 비밀번호 확인.
- 오류는 칸 아래에: "현재 비밀번호가 올바르지 않습니다", "8자 이상 입력하세요", "새 비밀번호가 서로 다릅니다". 오류가 나면 세 칸 모두 비운다(비밀번호는 다시 채우지 않음). [FR10.3] [NFR3] [assumption]
- 바꾸면 알림 "비밀번호를 바꿨습니다."

### S20 권한 없음, 찾을 수 없음, 오류 [FR1.4] [FR10.3]

- 권한 없음: 공통 틀 안에 "권한이 없습니다. 이 화면은 관리자만 쓸 수 있습니다." + [대시보드로].
- 찾을 수 없음: "요청한 화면이나 자료를 찾을 수 없습니다." + [대시보드로].
- 예상하지 못한 서버 오류: "처리 중 문제가 생겼습니다. 잠시 후 다시 시도해 주세요." 화면에 오류 코드나 기술 내용을 보여주지 않는다. [NFR3]
- 화면 안의 버튼 요청(입금, 승인 등)이 실패하면 페이지를 바꾸지 않고 알림 영역에 같은 문구를 보여준다.

## 5. 모든 화면에 공통인 상태

| 상태 | 보여주는 방법 |
|---|---|
| 빈 상태 | 표 자리에 이유와 다음 행동을 글로 쓴다(예: "등록된 상품이 없습니다. 첫 상품을 등록해 주세요." + 버튼). 조건 검색 결과가 없을 때는 "조건에 맞는 …이 없습니다" + [조건 초기화] |
| 불러오는 중 | 화면은 서버가 그려서 보내므로 따로 없다. 창 안의 검색(S12-1)과 버튼 동작(입금, 승인)은 버튼을 끄고 "처리 중..." 글자를 보여준다 |
| 성공 | 화면 제목 아래 알림 영역에 초록색 알림과 글자("저장했습니다" 등). 5초 뒤 사라지지 않고 닫기 버튼으로 닫는다 [assumption] |
| 입력 오류 | 칸 아래 빨간 글자로 이유, 칸 테두리 강조, 화면 위 알림에 "입력값을 확인해 주세요. 오류 n건". 입력한 값은 유지(비밀번호 칸 제외) [FR10.3] |
| 서버 거부 | 재고 부족, 권한 없음처럼 서버가 거부한 이유를 알림 영역에 글자로 보여준다 |
| 로그인 만료 | 로그인 화면으로 보내고 "로그인 시간이 지나 다시 로그인해 주세요." [FR1.5] |
| 긴 글자 | 상품명(최대 100자)과 상호는 표에서 두 줄까지 보이고 넘치면 말줄임표, 마우스를 올리거나 상세 화면에서 전체를 본다 [assumption] |
| 많은 자료 | 목록은 모두 20건 페이지. 판매 1만 건에서도 화면이 2초 안에 열리도록 목록과 실적은 서버에서 거르고 센다 [FR10.4] [NFR10] |

금액은 모두 천 단위 쉼표와 "원"을 붙이고 표에서 오른쪽 정렬한다. 날짜는 `2026-11-05`, 일시는 `2026-11-05 14:20`(Asia/Seoul) 형식이다. [NFR7] [NFR8]

## 7. 가정

승인 전에 바꾸실 수 있습니다.

- 할부 개월 수는 1~36이고, 첫 예정일 기본값은 판매일의 다음 달 같은 날, 없는 날짜는 그 달 마지막 날이다.
- "입금" 버튼은 가장 앞의 미입금 회차에만, "입금 취소"는 가장 뒤의 입금된 회차에만 켠다. 연체 규칙(FR7.5)과 화면을 맞추기 위해서다.
- 입금·입금 취소는 관리자만 한다(요구사항의 입금 등록 권한을 그대로 따름).
- 판매 금액을 입금 합계보다 작게 바꾸거나, 모든 회차가 입금된 판매의 금액을 바꾸는 것은 거부한다. 입금이 있으면 개월 수와 결제 수단을 바꿀 수 없다.
- 외상·할부를 고른 뒤 거래처를 "거래처 없음"으로 바꾸면 결제 수단을 현금으로 되돌린다.
- 품목 추가 창에는 판매 중이고 재고가 있는 옵션만 고를 수 있게 하고, 입고에서는 판매 중지 옵션도 고를 수 있다.
- 직원 대시보드에는 매출 합계와 연체 판매가 없고, 최근 판매 목록의 개별 판매 금액은 보인다.
- 직원은 상품·거래처·판매를 조회할 수 있으므로 재고 변동 내역(S07)과 거래처 상세(S10)도 볼 수 있다.
- 성공 알림은 자동으로 사라지지 않는다. 화면 주소(S03~S19)는 제안이며 Domain Design에서 확정한다.
- 판매 번호는 `S-0123` 형식으로 보여준다(형식은 Domain Design에서 확정).
